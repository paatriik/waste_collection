# Danderyd waste-collection source

Staging repo for adding **Danderyds kommun** (Stockholm, Sweden) to
[mampfes/hacs_waste_collection_schedule](https://github.com/mampfes/hacs_waste_collection_schedule).

## State: ready to submit

Danderyd runs **EDP Futureweb**, a platform upstream already supports generically in
`edpevent_se.py`. No new source module is needed. The whole change is
`patches/0001-edpevent_se-add-danderyd.patch`: two files, 37 added lines.

An earlier plan in this repo built a standalone `danderyd_se.py` module. That was wrong —
it was drafted without network access and assumed a bespoke backend. It has been deleted.
`research/NOTES.md` records how the platform was identified and what the API returns.

## What the patch does

1. Adds a `danderyd` entry to `SERVICE_PROVIDERS`, pointing at
   `https://future.danderyd.se/Danderyd/EDPFutureweb/SimpleWastePickup`.
   `EXTRA_INFO` is derived from that dict, so the README listing follows automatically.
2. Adds two `TEST_CASES` covering nine of Danderyd's thirteen waste streams.
3. Adds ten `ICON_MAP` keys for the waste types Danderyd returns that upstream did not
   yet map. Purely additive — no existing key changes value, so other EDPEvent providers
   can only gain icons where they previously fell back to `mdi:help`.
4. Updates `doc/source/edpevent_se.md`: the service list, a worked YAML example, and the
   address-lookup link.

## Verify it

```bash
bash research/setup_dev.sh
```

Clones upstream, builds a venv, applies the patch, runs the CI gate, lints, and does a
live fetch. Idempotent. Needs network access to `github.com` and `future.danderyd.se`.

Two things that will waste your time otherwise, both handled by the script:

- **Run ruff via the repo's own `ruff.toml`.** The repo ignores `E203,E501,E721`. A
  hand-rolled `--select E,F,W,I` reports four pre-existing long lines that CI ignores.
- **Skip `homeassistant`.** It is ~200 MB, pins Python >= 3.12, and the structural tests
  do not import it. Installing `requirements.txt` wholesale fails on Python 3.11 and
  takes the other fifteen packages down with it.

## Submitting

Upstream takes PRs only from a fork; this repo cannot open one.

```bash
# 1. Fork mampfes/hacs_waste_collection_schedule to your account, then:
git clone https://github.com/<you>/hacs_waste_collection_schedule.git
cd hacs_waste_collection_schedule
git checkout -b add-danderyd-edpevent master        # never commit to the fork's master

# 2. Apply the patch.
git apply /path/to/patches/0001-edpevent_se-add-danderyd.patch

# 3. Confirm the diff is exactly two files.
git diff --name-only

# 4. Commit and push, then open the PR against mampfes/...:master.
```

Suggested title: `Add Danderyds kommun to edpevent_se`.

Mention in the PR body that the two test cases were run live and that the `ICON_MAP`
additions are additive. Reviewers check both.

### Upstream rules that bite

- The diff must contain **only** those two files. `README.md`, `info.md`, `sources.json`,
  `source_metadata.json` and `translations/*.json` are generated by CI post-merge.
  Never run `update_docu_links.py` in a branch.
- `doc/source/edpevent_se.md` is hand-maintained in full, service list included. The
  `<!--Begin of service section-->` markers look generated but are not — the constants
  in `update_docu_links.py` are dead code. The list is alphabetical.
- `ICON_MAP` values must be `Icons` enum members, not raw `"mdi:…"` strings. Do not
  extend the enum in a source PR.
